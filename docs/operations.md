# 日常操作

界面分六块：**工作概览 / 邮箱 / 发送任务 / 回复与跟进 / 批量任务 / 发件设置**。
这一页讲清楚一条完整的链路：加账号 → 导入 → 编排 → 发送 → 收信 → 跟进。

## 一、发件账号（发件设置）

| 字段             | 说明                                                     |
| ---------------- | -------------------------------------------------------- |
| 名称             | 内部标识，随便起                                         |
| 发件邮箱         | 收件人看到的 From 地址                                   |
| SMTP 主机 / 端口 | 例如 `smtp.gmail.com` / `465`（SSL）或 `587`（STARTTLS） |
| 用户名 / 密码    | Gmail 必须用**应用专用密码**，不能用登录密码             |
| 仅回复           | 勾上后该账号不参与批量分配，只用来收信和回复             |
| 不可用           | 临时停用：已预约的任务会暂停，队列里的邮件退回待发送     |

几个约定：

- 保存后先点**测试连接**。测试只做认证，不会真的发邮件。
- 「仅回复」账号哪怕 SMTP 配错也不影响批量发送。
- 停用账号不会删除密码和历史记录，重新启用即可继续用。

## 二、导入批量任务

第一行必须是表头，三列必需：

| 列名             | 作用                         |
| ---------------- | ---------------------------- |
| `business_email` | 收件人地址，会校验格式并去重 |
| `email_subject`  | 邮件主题，可用 `{{变量}}`    |
| `email_content`  | 邮件正文，可用 `{{变量}}`    |

其余列自动变成可用变量，例如 `姓名`、`公司`、`channel_name`，在正文里写 `{{姓名}}` 即可，
**每行渲染成各自的内容**，收件人之间互相看不到。

导入的关键行为：

- 一行 = 一封邮件。
- 重复地址、格式错误的行会被排除，界面里能看到排除了多少行、为什么。
- 导入**不等于发送**，只是把内容存进来。
- 导入任务本身是一个不可变的来源快照：后面拆分成多少个执行子任务，都能追回到原始文件和工作表。
- 可选「检查地址」先做 DNS/MX 预检，见 [address-preflight.md](address-preflight.md)。

## 三、安排发送

1. 选**来源任务**（刚导入的那份）；
2. 选**发件账号**（可多选，会按数量均分）；
3. 看**预览**：左边是收件人真实看到的内容，可以逐封翻；预览阶段不落任何发送记录；
4. 设**节奏**：账号内随机间隔、是否留档副本、是否立即发送或预约到某个时间；
5. 提交：保存草稿 / 立即发送 / 加入预约。

提交时的校验（都不可跳过）：

- 每个收件人最终渲染出的主题+正文必须唯一，重复内容会被拦下；
- 必须有可用账号，且「仅回复」账号不参与；
- 预览提交会带上一个指纹，指纹过期（来源数据变了）就要求重新预览；
- 提交带幂等键，重复点击不会创建两个任务。

## 四、状态怎么读

任务级：

| 状态         | 含义                       |
| ------------ | -------------------------- |
| 草稿         | 还没提交                   |
| 已预约       | 到时间才会开始             |
| 发送中       | 正在提交                   |
| 未排期       | 没有可用账号或还在等处理   |
| 需要处理     | 有失败/待核对，需要人看    |
| 等待自动重试 | 临时性失败，按退避重试中   |
| 需要人工确认 | 结果不明，**必须人判断**   |
| 已完成       | 全部结束                   |
| 部分异常     | 有失败行                   |
| 已取消       | 被取消，未发部分退回待发送 |

单封邮件：

| 状态           | 含义                                                    |
| -------------- | ------------------------------------------------------- |
| 待发送         | 排队中                                                  |
| 提交中         | 正在和 SMTP 交互                                        |
| 发送服务已接受 | SMTP 返回 2xx，**只代表对方服务器收了，不保证进收件箱** |
| 发送失败       | 明确失败，可重试                                        |
| 待核对         | 结果不明（超时、连接中断、5xx 后无回执）                |

> **最重要的一条规则：`待核对` 永远不会被自动重发。**
> 因为对方可能已经收到了。必须先去发件箱/收件箱核实（同一 `Message-ID`），
> 确认没发出去才手动重试。盲目补发 = 对方收到两封一模一样的信。

## 五、邮箱与回复跟进

- 邮箱页按会话聚合，能看完整往来。
- 回复与跟进页把回信分成三类：**需要回复 / 已处理 / 退信**。
- 「已处理」是人工处置状态，和「是否收到回复」是两个维度，不会被互相覆盖。
- 退信（DSN）单独归类，默认视为已处理；导出跟进表时会带上。
- 支持按导入任务、时间段筛选，并导出 xlsx 交给别人接手。

判断「这条是不是真的回复」的经验规则：

- 平台通知（`noreply@` 发来的）忽略；
- 退信单独看，别当回复；
- 最后一条消息是**对方**发的，才算等我们回。

## 六、批次报表

每个批次有两份东西，别混：

- **执行报告**：谁发了、发了什么、成功/失败/待核对；
- **留档副本**：把内容抄送/存档到自己的邮箱，用于事后举证。

副本可以不发，报告不受影响。报表里的「已发送」一律指 SMTP 接受。

## 七、每日检查清单

1. 「发送任务」里看有没有 `需要处理` / `需要人工确认`；
2. 「回复与跟进」看 `需要回复` 有没有堆起来；
3. 看「批次报表」里最近备份时间是不是今天；
4. 邮件量大的话看有没有 `等待自动重试` 卡住不动。
