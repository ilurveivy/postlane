# 邮箱预热：让新邮箱先「像人一样」发几天

新域名 + 新邮箱直接群发冷邮件，是最快的封号方式。预热（warm-up）的目标不是
「攒积分」，而是让收件方（Gmail / Outlook / Yahoo）在**真实互动**里看见这个发件人
是正常的人：有来有回、有人读、有人从垃圾箱里把它拖回来。

产品里只有**互寄**这一种预热：池子里的账号来回寄几封普通邮件。
下面先说清楚它到底有什么用、没什么用，再说怎么打开。

## 一、它有用吗 —— 分开看

| 期待                                                     | 结论                                          |
| -------------------------------------------------------- | --------------------------------------------- |
| 让 Gmail 对陌生收件人「高看我一眼」                      | ❌ 基本没有。同域互寄的信，过滤系统很容易识别 |
| 让新邮箱别一直是死的（零发信量的账号突然发 50 封很可疑） | ✅ 有一点，普通双向流量是自然的               |
| **提前知道我的信到底进不进收件箱**                       | ✅✅ **这是真正的价值**                       |
| 判断 SPF/DKIM/DMARC 是不是配好了                         | ✅ 顺手就验了（进垃圾箱通常就是这里出问题）   |

所以预热在这里是**体检 + 温和的日常流量**，不是声誉神器。
真正决定冷邮件能不能进收件箱的，还是「发给对的人 + 有回复 + 没人投诉退信」，
这些靠的是回信和名单质量，不是互寄。

但「体检」这一条就值得做：没有任何其他办法，能在发给陌生人之前知道
「我现在这封信，落到收件箱还是垃圾箱」。

## 二、什么时候开

- **只有一个邮箱** → 不需要，也开不了（没有互寄对象）。设置页会说清楚原因。
- **两个及以上邮箱** → 可以开。效果最好的是**跨服务商**：你的域名 ↔ 一个 Gmail，
  这时的落箱结果才代表真实的 Gmail 判断；两个同域账号互寄只能验 SMTP 通不通。

## 三、怎么开

设置 → 邮箱预热：

```
[x] 启用互寄预热                 ← 至少两个可用账号才能勾
    参与互寄的账号
      [x] a@yourdomain.com
      [x] b@yourdomain.com
      [x] you@gmail.com
    每个账号每天发几封  [3]      ← 1–10，默认 3
[保存预热设置]  [立即试发一轮]  [立即检查落箱]
今日已互寄 6 封 · 待检测 0 封 · 近 6 封里有 收件箱 6 / 垃圾箱 0 / 未到 0
```

规则（都是默认值，不需要配置）：

| 项             | 值                                         | 为什么                         |
| -------------- | ------------------------------------------ | ------------------------------ |
| 每账号每天上限 | 3 封（可改 1–10）                          | 预热是「别太闲」，不是「多发」 |
| 两次之间       | 至少 40 分钟                               | 一次发十几封反而是机器特征     |
| 时段           | 每天 09:00–21:00（新加坡时间）             | 半夜发信很可疑                 |
| 配对           | 轮换，永不发给自己                         | 4 个账号能转很多天不重复       |
| 内容           | 中性话题库，随机取，纯文本、无链接、无签名 | 一模一样的措辞是指纹           |
| 额度           | **不占**冷邮件的每日上限                   | 它不打扰陌生人                 |
| 急停 / 暂停    | 跟着全局停发一起停                         | 不会绕过「全部停发」           |

「立即试发一轮」跳过后面的间隔和时段限制（你点的按钮），但**不会超过当天上限**，
所以点两次不会把账号刷成 30 封。

## 四、落箱检测怎么工作

每封互寄信都带一个我们自己生成的 `Message-ID`。发出去 1 分钟后，用**收件账号的 IMAP**
去找这封信落在哪个文件夹：

| 结果                          | 含义                      | 面板上    |
| ----------------------------- | ------------------------- | --------- |
| 在 `INBOX`                    | 正常                      | 收件箱 +1 |
| 在 `Junk` / `Spam`            | 信誉还不够，或 DNS 没配好 | 垃圾箱 +1 |
| 三次都找不到（或超过 6 小时） | 投递被拒/丢了             | 未到 +1   |

一次找不到不会立刻判「没到」（邮件不是瞬时的），会再试，最多三次。
落箱率按**最近 20 封**算 —— 面板上的百分比就是这个数。

读法：

- 一直 100% 收件箱 → 可以按 [发送纪律](sending-policy.md) 的节奏加量；
- 出现垃圾箱 → **先别发冷邮件**，去查 SPF/DKIM/DMARC 和域名历史（新域名更常见）；
- 出现「未到」→ 大概率是 SMTP 层就被拒了，看账号的报错。

## 五、想做得更像真人（可选，暂未实现）

现在的互寄只做「发 — 收 — 检查」。要更接近真人，还可以加这些动作：

- 收件方把信标记已读 / 加星 / 加进联系人；
- 发现进了垃圾箱就**移回收件箱并点「非垃圾邮件」**（这是最强的正向信号）；
- 回信（一来一回，而不是单向发）；
- 话题库里准备多套变体，按域名轮换。

这些都要读收件方的 IMAP 并做写操作，比现在的「只读检测」复杂得多，
而且收益边际递减 —— 建议先用一段时间落箱数据，确认真的需要再上。

## 六、第三方预热网络（不建议自建）

市面上有付费的预热服务（Warmy / Mailreach / Lemwarm 这类），它们有一批真实用户池，
你的账号和**别人的账号**互寄，效果比自寄好，因为收件方看到的是不同组织在跟你往来。
代价是付费 + 把邮箱的 IMAP/SMTP 授权给第三方。

自托管产品没法内置这种网络 —— 它本质是一项**服务**，不是一个开关。
Postlane 不实现它，也不阻止你用；如果两边同时开自动化，注意别让它们打架。

## 七、没有这个功能时能怎么办

手动跑也一样，只是慢：

```bash
# 每天用另一个邮箱给你的主发信邮箱发 3–5 封普通邮件，互相回复，
# 然后去 Gmail 里看它们落在收件箱还是垃圾箱 —— 这就是最原始的预热。
```

而且**在落箱没确认之前，把冷邮件额度手动压住**：自动 ramp 第 1 天就给 20 封，
如果信其实一直进垃圾箱，这 20 封是在拿域名赌。
