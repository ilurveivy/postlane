# 落箱自检：发一封，看它到底进不进收件箱

冷邮件最大的盲区不是文案，是**你根本不知道对方会不会在垃圾箱里看到它**。
所有「发送成功」都只代表 SMTP 服务器收下了，不代表 Gmail 会把它放进收件箱。

自检就是把这一件事测出来：从发件账号发一封普通邮件到**你自己的另一个邮箱**，
然后读回收件方邮箱，告诉你它落在哪儿。

## 怎么用

设置 → 落箱自检：

```
发件账号    [你有域名的主发信邮箱          ▾]
收件邮箱    [你的 Gmail（在邮趣里也配了）  ▾]
[发一封测试信]  [检查落箱]

收件箱  a@yourdomain.com → you@gmail.com · 11-11 22:14 · 收件箱：链路正常，可以按节奏发
历史 4 次：收件箱 3 / 垃圾箱 1 / 没到 0
```

1. 选发件账号和收件邮箱（**收件邮箱必须是你在邮趣里配好的账号** —— 落箱要靠它的 IMAP 去读）；
2. 点「发一封测试信」；
3. 等 1 分钟，点「检查落箱」（后台每 90 秒也会自动查一次）。

## 三种结果怎么读

| 结果       | 面板上                                                 | 该做什么                                                      |
| ---------- | ------------------------------------------------------ | ------------------------------------------------------------- |
| **收件箱** | 收件箱：链路正常，可以按节奏发                         | 可以给真实名单发了，按[发送纪律](sending-policy.md)的节奏加量 |
| **垃圾箱** | 进了垃圾箱：先别发冷邮件，查 SPF/DKIM/DMARC 和域名历史 | 见下面的排查顺序                                              |
| **没到**   | 没到：大概率在 SMTP 层就被拒了                         | 看账号的报错，通常是授权码、发信量或 IP 被拒                  |

一次没找到**不会**立刻判「没到」（邮件不是瞬时的），会自动再试，最多三次；
超过 6 小时还找不到才记「没到」。

进了垃圾箱，按这个顺序查：

```bash
# 1) SPF / DKIM / DMARC 是否配好（邮趣的域名体检会直接告诉你）
# 2) 域名是不是刚注册的（新域名前两周最容易进垃圾箱）
# 3) 这封测试信里有没有可疑内容 —— 自检用的是中性短句，如果连它都进垃圾箱，问题在域名不在文案
# 4) 换一个收件服务商再测一次：Gmail 进、Outlook 不进，说明是单个服务商对你的判断
```

## 两个必须知道的限制

1. **收件邮箱必须是你自己的、且配在邮趣里的账号。** 因为「查落箱」是打开那个邮箱的 IMAP
   去搜这封信，邮箱不在邮趣里就没有凭据可读。
2. **同一账号寄给自己，只验证「服务商内部投递」。** 真正有参考价值的是**跨服务商**
   （你的域名邮箱 → Gmail）。所以最好把自检用的 Gmail 也加到账号列表里，
   它只用来收信，不需要发信。

## 为什么不做「互寄预热」

一开始我按「多个邮箱互相发信养号」的方案做过一版，后来砍掉了，原因写在这里免得以后再走一遍：

| 想法                         | 实际                                                        |
| ---------------------------- | ----------------------------------------------------------- |
| 互寄能提升对陌生收件人的信誉 | ❌ 同域互寄的信过滤系统很容易识别，几乎不产生有效声誉       |
| 互寄让新邮箱「像活的」       | ✅ 有一点，但收益远小于它占用的注意力                       |
| 互寄能顺便测落箱             | ✅ 这才是真需求 —— 但它只需要**一封**测试信，不需要持续互寄 |

也就是说：**要的是检测结果，不是检测过程**。持续互寄换不来信誉，只是自己给自己制造流量；
而一封按需发出的测试信，就能回答「我现在能不能进收件箱」这个问题。
所以最终只留下了自检。

如果你真的想把互动做得更足（标记已读、从垃圾箱拖回收件箱、回信），
那是**付费预热服务**在做的事（Warmy / Mailreach 这类，有真实第三方用户池）。
自托管产品没法内置这种网络 —— 它是一项服务，不是一个开关。

## 什么时候该测

- **拿到新域名 / 新邮箱的第一天**，测一次，确认链路通了再发第一批；
- **改过 SPF/DKIM/DMARC 之后**，测一次确认改动生效；
- **发了几批冷邮件之后**，测一次看有没有被降权；
- **某批邮件突然没人回**（尤其是之前回得挺好），先测一次 —— 往往是落箱已经变差了。
