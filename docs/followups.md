# 多步跟进：第二封、第三封

一封冷邮件没人理，不代表这个人没兴趣 —— 更常见的情况是「看到了，忘了回」。
跟进序列就是把这件事变成流程：首封发出后，隔几天再补一封，再隔几天补最后一封，
**对方一有回音就立刻停**。

## 表格里怎么填

导入的表格多认两个可选列：

| 表头         | 含义                               | 不填会怎样               |
| ------------ | ---------------------------------- | ------------------------ |
| `第二封跟进` | 首封之后发给同一个人的第二封正文   | 没有第二封，也没有第三封 |
| `第三封跟进` | 第二封之后发给同一个人的第三封正文 | 没有第三封，只有第二封   |

两列都是**选填**，空着就表示这条线索只发首封。表格里其它列（`business_email`、
`email_subject`、`email_content` 以及任何自定义列）的写法完全不变。

```csv
business_email,email_subject,email_content,第二封跟进,第三封跟进
kim@acme.com,想问下排期,你好 Kim，我是……,补一句：这周有空看吗？,主题：最后一封
最后一封正文……
```

也认这些别名（当成同一个列）：
`第2封跟进` / `跟进2` / `follow_up_2` / `second_follow_up`，以及对应的 `3` 系列。

## 单元格里写什么

- **整格就是正文。** 除非你在第一行单独写标题。
- 想自己定标题，就让单元格以 `主题：`（或 `标题：` / `Subject:`）开头，
  第一行之后全是正文：

  ```
  主题：关于上封邮件里的排期
  你好 Kim，上周提到的排期我整理了一页……
  ```

- 不写标题时自动用 **`Re: <首封标题>`**，并且带上首封的 `In-Reply-To` / `References`
  —— 在对方邮箱里这是**同一个会话**里的第二封，不是又一封新的冷邮件。
- 跟进正文里同样可以用 `{{变量}}`。用了首封没有的变量，**建任务时会直接报错**，
  不会发出一个名字空着的跟进。

## 什么时候发

默认间隔：

```
首封  ──5 天──▶  第二封  ──10 天──▶  第三封
```

天数在建任务时可按任务调整（第二封在首封后 N 天、第三封在第二封后 M 天，1–90 天）。
是这个任务里每个人都一样的相对间隔 —— 不是日历日期，所以批次晚开始一天，
整个序列跟着顺延，不会出现「跟进比首封还早」这种时间穿越。

严格的条件（缺一条都不发）：

1. 上一封**确认已送达**（`sent`）。`uncertain`（提交结果不明）不发 ——
   万一那封其实没出去，「补一句」就变成第一封莫名其妙的冷邮件；
2. 到点了还没收到回信（IMAP 抓到回复即停）；
3. 没有退信、没有退订、这条线索没被手工停掉；
4. 发件账号仍然可用、没触发急停、当前在发送时段内、账号当天还有额度。

## 有额度和节奏吗

有，而且**每一封都算**：跟进和首封共用同一个账号的每日上限（新账号 20 封起步那套）
和同一个发送时段。一次 300 人的任务、每人都填了两封跟进，就是 900 封邮件，
按额度分好几天发完 —— 不会因为「跟进」就绕开限流。

## 任务的完成状态怎么算

- **任务状态只表示首封那批的结果**：首封都处理完，任务就是「已完成」，
  报表和批次报告也照常在那个时候出，不会因为还有跟进没发而推迟 15 天。
- 跟进是挂在这批之后的**独立队列**：任务已经「已完成」也照样会按时把第二、三封发出去。
- 想确认还有多少跟进没发：任务详情里每个人后面会显示 `跟进 2/3`，
  以及这一行的「下一封跟进：时间」。跟进停下时（回信 / 退订 / 退信 / 结果不明）
  会写明原因，例如「跟进已停：已收到回复」。

## 边界情况

| 情况                               | 行为                                          |
| ---------------------------------- | --------------------------------------------- |
| 只填了第三封、第二封空着           | 序列在空格处结束 —— **不会跳发第三封**        |
| 首封永久失败（`failed`）           | 没有跟进。没什么可跟进的                      |
| 首封结果不明（`uncertain`）        | 没有跟进，直到人工核对                        |
| 跟进提交时连接断了（结果不明）     | **不重发**，标为需人工核对，这条序列停住      |
| 跟进被 SMTP 明确拒收               | 按同一封重试，最多 3 次；仍失败则该人停止跟进 |
| 中途退订（点链接或回信说退订）     | 立刻停，压制名单生效，后续批次也不会再发      |
| 表格里两列都有，但某人只填了第二封 | 只发第二封                                    |

## 上线前自查

```bash
# 1) 确认列名能被识别（建任务第 1 步的「自动识别」或手动选列）
# 2) 预览页会写：「多步跟进：第二封 12 人（首封后 5 天）、第三封 8 人（第二封后 10 天）」
# 3) 先用一个小批次（比如 3 个人）跑一轮，把间隔临时改成 1 天 / 1 天验证节奏
```

间隔改成 1 天只影响那一次任务；验证完记得改回来。
