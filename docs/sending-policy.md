# 发送纪律：默认就会替你守住的 5 条线

冷邮件最容易翻车的不是文案，是**发太快、发太晚、发给假地址**。这几条不是「建议」，
是平台默认行为，不需要你记得配置。

---

## 1. 每个账号每天有上限，新账号从 20 封起

| 账号已启用天数 | 每天上限       |
| -------------- | -------------- |
| 1–3 天         | 20 封          |
| 4–7 天         | 30 封          |
| 8–14 天        | 50 封          |
| 15–30 天       | 100 封         |
| 31 天以后      | 200 封（硬顶） |

- 「天数」按**新加坡时间**的日历日计算，基准是这个账号的创建时间（老数据用验证时间）。
- 在「发件设置」里可以给某个账号指定更小的上限；填多大也**不会超过 200**。
- 当天额度用完后，任务不会失败，而是**自动排到下一个发送窗口**继续，剩余收件人一个都不丢。
- 已发出（`sent`）和结果待核对（`uncertain`）都计入当天用量 —— 不确定的那封按「已经发了」算，
  宁可少发一封，也不要重复打扰同一个人。

为什么要有爬坡：新域名/新邮箱在头几天突然发几百封，是最典型的垃圾邮件特征，
一旦被判定，后面几周都救不回来。20 → 30 → 50 → 100 → 200 是最常见的安全曲线。

---

## 2. 只在指定时段发送（默认工作日 09:00–18:00，新加坡时间）

每个发送任务都可以单独设置：

- 开关：只在窗口内发送 / 不限时段；
- 起止时间（如 `09:00`–`18:00`，结束时刻不含在内）；
- 周一到周日可任意勾选（默认周一到周五）。

窗口外任务会挂起并显示下一次可发送时刻，**不会深夜发信**。任务不会过期，只是等着。
时区固定为 `Asia/Singapore`（UTC+8，无夏令时），换一台电脑也不会变。

---

## 3. 发送前先筛地址：占位符、退信地址、角色邮箱

详见 [address-preflight.md](address-preflight.md)。要点：

- `your.email@…`、`john.doe@…`、`example.com` 这类占位符，以及 `noreply@`、`postmaster@`
  这类永远不会有人读的地址，在**发送前**被排除；
- `info@`、`contact@`、`sales@` 这类角色邮箱只标记不排除；
- 同一个地址**已经在别的任务里发过**，本次自动跳过，避免同一个人收到两封。

---

## 4. 退订说明可以按任务打开

「新建邮件任务 → 发送设置 → 退订说明」：

- **不加**（默认）：一对一私信风格，适合真实的个人征询；
- **加**：正文末尾追加一行「回复『退订』即可，我会立即停止发送」，同时带上
  `List-Unsubscribe` 邮件头，收件端会显示一键退订。

自己写在正文里的退订措辞不会被重复追加。

> 已经回复「退订」的人，请在「回复与跟进」里标记，平台会把他加入停发名单。

## 5. 发件域名体检 + 一键急停

### SPF / DKIM / DMARC 体检

「保存并测试连接」时除了验证 SMTP，还会查这个发件域名的 DNS 记录：

| 缺失                     | 后果                           | 提示                                     |
| ------------------------ | ------------------------------ | ---------------------------------------- |
| 没有 SPF                 | 从本机发出的信很容易进垃圾箱   | 建议改为拒绝；缺失时如实提示，不阻断     |
| 没有 DMARC               | 收件方无法确认你授权了来源     | 建议至少加一条 `v=DMARC1; p=none`        |
| `p=none`                 | 只观察不拦截                   | 稳定后建议升级到 `quarantine` / `reject` |
| 常见选择器没有 DKIM 公钥 | 可能只是服务商使用自定义选择器 | 提示「如果是自定义选择器可以忽略」       |

只做 DNS 查询，不发送邮件，也不接第三方验证服务；DNS 故障时降级为「未知」，绝不阻断保存。

### 一键急停

顶栏右侧「全部停发」：立刻停掉**所有**出站邮件 —— 活动任务、回复草稿、报表投递一起停。
正在发送的那一封会发完（SMTP 已经接管，撤回会变成「不确定」状态），其余全部挂起。

- 停发状态会持久化，重启平台仍然有效；
- 页面顶部会常驻红色提示，写明停发原因和开始时间；
- 点「恢复发送」后从当前收件人继续，**不会重发已经发过的**。

也可以在脚本里调用（需要页面 token）：

```bash
curl -X POST http://localhost:4173/api/send-halt \
  -H "x-postlane-token: $TOKEN" -H "Content-Type: application/json" \
  -d '{"halted":true,"reason":"名单有问题"}'
```

## 附：Message-ID 现在用你自己的域名

以前邮件头的 `Message-ID` 长这样：

```
<1f3c…@postlane.local>
```

`.local` 是 IANA 保留的伪域名，DNS 里并不存在。**伪造或无法解析的 Message-ID 域名
是垃圾邮件评分的加分项**（SpamAssassin 等会直接扣分），收件方也可能因此把信判成可疑。

现在改成发件人自己的域名：

```
<1f3c…@your-domain.com>
```

这个域名本来就在 SPF/DKIM 里被授权发信，所以 Message-ID 与信封发件人一致，不再自相矛盾。
如果账号还没填发件人（理论上不会），退回 `postlane.local` 作为兜底。
